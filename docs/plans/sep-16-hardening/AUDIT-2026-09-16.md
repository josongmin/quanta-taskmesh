# Sep-16 hardening — 구현 직후 적대적 감사와 그 처리

- 날짜: 2026-09-16 (구현 완료 직후, 같은 날)
- 방식: 독립된 3-track 감사를 병렬로 실행 — (1) engine/runtime 정합성, (2) 증명 강도
  (test·mutation·model-check가 실제로 무엇을 증명하는가), (3) tooling/CI/deps/docs/계약.
  각 track은 코드를 수정하지 않고 반례를 재현했다.
- 결과: P0 3건, P1 12건, P2 ~30건, P3 다수. **모두 처리했다** — 코드 수정 + 실제 test,
  또는 "동작 유지"를 근거와 함께 명시. 아래 표가 finding → 처리 → 증거다.
- 계약 변경은 [ADR 0003](../../adr/0003-sep-16-hardening-contracts.md) D05/D08/D09/D10 개정과
  D13–D16에 기록했다.

## 처리 원칙

1. 짜치는 test 금지: 모든 새 test는 mutation(`tools/verification/mutations.json`)이나
   반례 재현으로 "이 test가 없으면 무엇이 통과하는가"를 보였다.
2. hang은 실패가 아니다: hang으로만 regression을 드러내던 test는 상한 + release-on-drop
   fixture로 assertion 실패가 되게 바꿨다.
3. 조용한 실패 금지: `()`를 반환하던 API, 무시되던 `bool`, 버려지던 deadline, 문자열로
   뭉개지던 실패는 모두 typed outcome이 됐다.
