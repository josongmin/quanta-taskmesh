# Mutation validation cadence

- Daily edits: don't run `just dev`, workspace-wide tests/lints, or `just mutants-critical` automatically. Run owner-scoped checks below; reserve CI and nightly gates for explicit qualification/release requests.
- Rust logic edits: `just dev-rust-fast <crate> [consumer-crate ...]` scopes Clippy to the changed package and runs its tests plus explicitly affected consumer-package tests in one Cargo invocation. Run owner tests even if test files are unchanged: they are the oracle for the changed logic. Use `dev` only for cross-package/shared-boundary changes; do not rerun unrelated packages by default.
- Python tooling edits: `just dev-python-fast <changed.py> <owner-tests>` runs Ruff on the changed files and pytest on the owning `tools/<area>/tests` suite. Changes to shared tooling (`tools/process_supervisor.py`, `tools/qualification/evidence.py`) require the suites that consume that shared owner.
- Rust test-only edits: use `just dev-rust-tests <crate> [consumer-crate ...]`; it skips production Clippy and batches the selected package tests in one Cargo invocation. Python test-only edits use `just dev-python-fast <test-file> <owner-tests>`. Do not run mutation campaigns unless the test's oracle strength or a curated mutation declaration changed.
- Focused mutation is opt-in for a critical changed branch or an oracle-strength question: use `just mutants-focused --package <crate> --file <path> --diff <unified-diff> --test-target <target>`. Use `--test-target lib` for unit tests. Add `--test-filter <exact-test-name>` only as a quick diagnostic; it does not establish that the rest of the target catches the mutant.
- Focused reports are diagnostic-only, never qualification receipts. A green diagnostic requires a complete raw denominator and a normal zero-exit producer process. Cache reuse requires an identical selected-package dependency/source/test fingerprint, execution and digest tool sources, file selection, toolchain, options, and exact test filter; a cached report must also retain its source snapshot identity and complete raw artifacts. Use `--refresh` to force another run.
- The selected dependency fingerprint uses the shared source digest, including each path's file kind, full permission mode, bytes, and symlink target. Path and content records are length-framed: changing the path set cannot be hidden by placing a serialized path record in another file's bytes. The framing change invalidates earlier focused cache keys. A mode or link-target change cannot reuse an earlier focused report.
- A producer leader that exits zero while leaving a process-group descendant is incomplete. The supervisor kills that group and reports no successful group exit status; curated, generated, and focused mutation verdicts must fail closed.
- A descendant that creates a new session escapes process-group signals. Its inherited capture pipes have a hard drain boundary after timeout and grace; the producer is timed out/failed. The supervisor cannot reclaim that escaped process, so host-side cleanup is separate.
- `--timeout` bounds each mutant inside cargo-mutants. `--campaign-timeout` separately bounds the complete focused run (default 86,400 seconds).
- A valid cache hit is checked before creating the isolated source snapshot; cache misses still run from an isolated snapshot.
- `taskmesh-doc-examples` reads README, external interface, and CHANGELOG outside its package directory during `build.rs`; those declared inputs participate in the focused cache key. An unparseable build input declaration fails closed.
- Inherited `CARGO_MUTANTS_*` settings are rejected by the shared campaign owner; they cannot silently change the denominator, timeout, or cache identity.
- Run `just mutants-critical` when its curated inventory/oracles change or for an explicit mutation investigation. Run `just mutants-generated` only for an intentional full-candidate audit or qualification. Focused runs do not cover downstream consumer tests.
